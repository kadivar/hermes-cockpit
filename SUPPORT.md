# Support

This project has one maintainer and no issue tracker. That is on purpose: every report arrives as something that can be
checked and merged.

## I have a question

Read [docs/](docs/) first: [concepts](docs/concepts.md), the [quickstart](docs/quickstart.md), the
[recipes](docs/customize/README.md) and the generated [references](docs/reference/). `cockpit doctor` and
`cockpit pack explain <key>` answer most questions about your own installation.

If the answer is not there, the documentation has a hole. **Open a pull request that adds the question and what you
found** to the page where you looked for it, even when your answer is partial. A question becomes a documentation pull
request, and the review is the answer.

## I found a bug

A report is a pull request: a test that fails for the reason you describe, with or without the fix. See
[CONTRIBUTING.md](CONTRIBUTING.md), or point your coding assistant at [AGENTS.md](AGENTS.md).

## I want a feature

Check first whether a pack can already do it: [docs/customize/](docs/customize/README.md) has one recipe per extension
point. Most requests end there. Otherwise, a pull request, as above.

## I found a vulnerability

Privately, never in a pull request: [SECURITY.md](SECURITY.md).

## What you can expect

Best effort, from one person. Only the latest release is supported.
